# Audit log

## Purpose

MEMORA records security-relevant mutations in the existing `audit_logs` table. The audit trail is workspace-scoped and append-only for direct application and administrative operations.

## Automatically recorded mutations

Migration `0008_audit_log_immutability.sql` installs PostgreSQL triggers on:

- `sources`
- `memories`
- `entities`
- `entity_relations`

Each INSERT or UPDATE creates an audit event in the same database transaction. If the business mutation rolls back, its audit event rolls back too.

Events use an action such as `sources.insert` or `memories.update`, the resource table and UUID, the active transaction's `app.user_id` as actor, and a timestamp generated by PostgreSQL.

## Data minimization

Audit metadata contains only the table name, operation, and names of changed non-sensitive columns. It never copies field values. Content, summary, metadata, attributes, aliases, descriptions, canonical names, titles, filenames, storage keys, checksums, external IDs, IP addresses and user-agent values are excluded from changed-field metadata.

Do not add request bodies, source text, memory content, tokens, credentials, invitation hashes, or provider payloads to audit metadata.

## Isolation and immutability

- Forced RLS permits reads only in the active workspace.
- Insert policy requires the event workspace to match the transaction workspace and the actor to be null or the current domain user.
- There are no application UPDATE or DELETE RLS policies.
- A PostgreSQL trigger rejects direct UPDATE/DELETE attempts even for privileged SQL sessions.
- Referential cascades remain available for workspace/account erasure. Such erasure removes the corresponding workspace-owned audit history; retention/export policy must be defined before production.

Runtime API connections must use the restricted non-owner, non-superuser, NOBYPASSRLS role. Migration credentials must remain separate.

## Validation

`packages/database/tests/audit-log.spec.ts` verifies transactionally recorded events, metadata minimization, workspace read isolation, actor-spoof rejection, application RLS denial of edits/deletes, and trigger-level immutability.
